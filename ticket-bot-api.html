Discord Ticket Bot — API Specification

A documentation-style interface definition for a Discord ticket tool (spec only; implementation may be internal Python functions).

1) Overview

The Discord Ticket Bot allows community members to submit support requests (e.g., bugs, feedback, reports) through Discord. Tickets are posted to a private reviewer-only channel where staff can triage, comment, assign, and close issues.

Note: This document defines an API-style interface (a contract). In the current prototype, these calls can be implemented as internal Python functions rather than real HTTP endpoints.

2) API Surface

Base URL shown for documentation purposes: https://api.example.com/v1

Method Endpoint Purpose
POST /tickets Create a new ticket from a Discord modal/panel submission.
GET /tickets List/search tickets (filter by status/category).
GET /tickets/{ticketId} Fetch a ticket including messages/notes and metadata.
PATCH /tickets/{ticketId} Update triage fields (status, assignee, tags).
POST /tickets/{ticketId}/messages Add a message (requester reply or staff-only note).
POST /tickets/{ticketId}/close Close a ticket (shortcut endpoint).
POST /tickets/{ticketId}/reopen Reopen a ticket.
GET /meta/categories List allowed categories (keeps input validation consistent).

3) Usage Example

Scenario: User submits a ticket → bot stores it → reviewer closes it.

[Discord User]
   | submit modal
   v
[Bot] -- POST /tickets --> [Ticket Store]
   | <-- ticketId --------
   v
[Private Review Channel Embed (ticketId + actions)]
   |
   | reviewer clicks Close
   v
[Bot] -- POST /tickets/{id}/close --> [Ticket Store]

4) API Reference

Create Ticket

POST/tickets — Creates a new ticket and returns its identifier.

Parameter Type Required Description
source string Yes Input source, e.g. "discord".
guildId string Yes Discord server ID scope.
requesterUserId string Yes Discord user ID of the requester.
category string Yes Ticket category (e.g., Bug, Feedback, Report).
title string Yes Short summary line.
description string Yes Full ticket description.

Returns

Field Type Meaning
ticketId string Unique identifier used in embeds, logs, and follow-up actions.
status string Initial ticket state (typically OPEN).
createdAt string (ISO-8601) Creation time.

Errors / Failure Cases

  • 400 Bad Request — missing title/description, category invalid.
  • 401 Unauthorized — missing/invalid auth (if secured).
  • 403 Forbidden — user/service lacks permission for that guild.
  • 429 Too Many Requests — spam/rate limiting triggered.
  • 500 Internal Server Error — unexpected failure (e.g., storage error).

Update Ticket

PATCH/tickets/{ticketId} — Updates ticket triage fields (partial update).

Parameter Type Required Description
status string No OPEN | IN_PROGRESS | CLOSED
assigneeUserId string or null No Reviewer Discord ID, or null to unassign.
tags array<string> No Labels like audio, ui, networking.

Errors

  • 404 Not Found — ticketId does not exist.
  • 409 Conflict — invalid state transition (e.g., already closed).
  • 403 Forbidden — caller not in reviewer role.

Close Ticket

POST/tickets/{ticketId}/close — Closes ticket and stores who closed it.

{
  "closedByUserId": "112233445566778899",
  "reason": "Reproduced and fixed in next build"
}

Errors

  • 404 Not Found — ticket does not exist.
  • 409 Conflict — ticket already closed.
  • 403 Forbidden — not a reviewer.

5) Notes (Implementation Mapping)

  • Current prototype: these “endpoints” can be implemented as internal Python functions (no real web server required).
  • Discord integration: modal/button interactions trigger the relevant actions (create, update, close).
  • Future expansion: a real REST API could enable a web dashboard, analytics, or external tooling.
